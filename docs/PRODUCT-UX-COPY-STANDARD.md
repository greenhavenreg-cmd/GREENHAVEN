# GreenHaven product UX and copy standard

GreenHaven must look and behave like a polished, production-ready consumer product — never a developer demo.

## Customer-facing interface
- Prefer short, familiar labels and clear actions.
- Do not add paragraphs to explain simple, discoverable features.
- Remove developer notes, implementation terminology, test status, placeholder explanations and repetitive onboarding copy from customer screens.
- Use icons and visual hierarchy where they make an action clearer; retain accessible names and clear labels for ambiguous or consequential actions.
- Keep empty states concise and give the user one obvious next step.
- Keep errors brief: say what happened and what the user can do next.
- Avoid repeating information already visible in the interface.

## When explanation is necessary
Use concise, contextual explanation only for payments, wallet balances, consent, security, identity verification, eligibility, financial settlement, irreversible actions, privacy choices and recovery from failures.

## Keep engineering detail out of the product
Technical documentation, migration notes, release gates, developer instructions and diagnostics belong in repository documentation or authorized operator tools — not in ordinary user-facing screens.

## Design acceptance
A screen should be understandable from its layout, labels and interaction patterns without a tutorial. Every sentence must earn its place. Preserve legal, safety, security and financial disclosures that users need to make informed decisions.
